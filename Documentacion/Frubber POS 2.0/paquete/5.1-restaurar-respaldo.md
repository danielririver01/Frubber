# Restaurar un respaldo de Frubber POS 2.0

1. **Reúne la copia.** Busca el archivo diario `FrubberPOS_backup_*.dump` y el archivo `FrubberPOS_roles_*.sql` con la misma fecha y hora. Conserva los originales y lleva una copia a otro PC. Entrega el archivo de roles solo a soporte, porque contiene datos de autenticación.
2. **Prepara el otro PC con soporte.** Pide una instalación PostgreSQL 18.6 y una base nueva y vacía llamada `frubber_restauracion`. Soporte prepara los roles y permisos de Frubber desde el archivo del respaldo y configura una conexión TLS verificada. Confirma el nombre del equipo de destino y el de la base antes de continuar.
3. **Restaura la copia.** En PowerShell, usa los datos de conexión entregados por soporte y cambia la ruta al archivo de respaldo. Ejecuta lo siguiente desde una ventana con acceso a las herramientas PostgreSQL.

   ```powershell
   pg_restore --list "C:\Respaldo\FrubberPOS_backup_FECHA.dump"
   pg_restore --single-transaction --no-owner --dbname frubber_restauracion "C:\Respaldo\FrubberPOS_backup_FECHA.dump"
   ```

   Si el primer comando falla, detente y pide a soporte revisar la copia. Si falla el segundo, conserva el error para que soporte revise el destino. La restauración en una sola transacción evita que quede una carga parcial.

4. **Comprueba los datos.** Pide a soporte habilitar un puesto de verificación y entra con tu PIN. Busca en **Historial** una venta anterior al respaldo y compara su número y total con el ticket. En **Productos**, comprueba la existencia de un producto conocido. Anota la fecha del respaldo, la fecha del ensayo y el resultado.
5. **Si el servidor original se dañó**, mantén las cajas fuera de servicio hasta que soporte valide la copia. Si cambió el código del servidor, solicita al dueño de Frubber una licencia emitida para el nuevo equipo, con el mismo cupo. Soporte actualiza el certificado y los perfiles protegidos de las cajas, confirma el acceso con el PIN y coordina el regreso a operación.
