# 2.4 Licenciamiento red y seguridad

Versión 2.0 · 19 de noviembre de 2026

## Continuidad de una licencia FRB1

1. Soporte confirma el código del equipo servidor y busca primero la FRB1 completa en el historial de emisiones de LicenseManager.
2. Si la encuentra, reutiliza esa licencia para el mismo equipo. Si la emisión no aparece, el dueño puede reemitirla para el mismo equipo como FRB1 y conservar el cupo de una caja. Procedimiento aprobado por el dueño el 19 de noviembre de 2026.
3. El migrador recibe el texto FRB1 completo, verifica firma e identidad del servidor y lo incorpora al destino junto con los datos. Si Windows permite abrir el sello del respaldo, compara su contenido con el texto firmado.

El respaldo SQLite 1.0 conserva el contenido canónico sellado mediante DPAPI. La firma se recupera del historial o mediante la reemisión aprobada. Para cambiar de servidor, soporte gestiona una licencia para el equipo de destino. Ampliar una FRB1 a dos o más cajas requiere FRB2 con el cupo contratado.

## Red y operación

El servidor usa una IP fija o reservada y conexión por cable. PostgreSQL 18.7 escucha en la interfaz prevista y el cortafuegos limita su puerto a la red del negocio. Las reglas pg_hba exigen TLS y roles por puesto. El certificado incluye el nombre o IP que usa el cliente y el instalador distribuye el certificado público. Cada puesto conserva su contraseña con DPAPI y verifica al servidor con VerifyFull.

Los roles de puesto tienen privilegios mínimos. La verificación de PIN se hace en el motor. El servidor arranca con Windows, ejecuta las migraciones y conserva el respaldo diario. La restauración se prueba aparte. AD-03 exige evidencia de las mitigaciones antes de distribuir.
